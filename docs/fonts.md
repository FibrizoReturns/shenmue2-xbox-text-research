# 字库审计：三个文件，三种命运

美版 `misc` 下有三件与 DC 日版同名的字库文件。同名不等于同源，逐字节比对后结论如下。

## 总表

| 文件 | Xbox 美版 | DC 日版 | 判定 |
|---|---|---|---|
| `dc_kanji.fon` | 351,270 B<br>`8669109EE72543CDEF91305A6D0CA018` | 351,270 B（四碟同）<br>`8669109EE72543CDEF91305A6D0CA018` | 逐字节相同 |
| `dc_kana.fon` | 7,680 B<br>`B7CD0B336C17DCF238F3901540CD75F2` | 7,680 B<br>`410C3C0306901D15F5C5A5C06913DD4D` | 174/256 槽相同 |
| `RYOU.FON` | 7,680 B<br>`66E52ECC0DE45F0D9E36E901FD711216` | 351,270 B<br>`B64E8F3A97DE4A987574B526EF101CB0` | 结构完全不同 |

数据源：`data/font_fingerprints.csv`（由 `tools/font_audit.py` 生成）。

## 1. 汉字库：三处同一

`351,270 = 7806 × 45`，即 7806 槽、每槽 45 B（24×15 点阵，每行 3 字节）。

同一份内容出现在三个位置：

1. 美版 `misc/dc_kanji.fon`
2. DC 日版 Disc 1/2/3/4 的 `MISC/DC_KANJI.FON`（四碟彼此也相同）
3. 美版 `misc/COLD.BIN` 偏移 `15328`（`0x3BC0`）起的 351,270 字节

验证：

```python
kb = open(xbox + r"\misc\dc_kanji.fon", "rb").read()
kd = open(dc + r"\1\MISC\DC_KANJI.FON", "rb").read()
cold = open(xbox + r"\misc\COLD.BIN", "rb").read()

assert kb == kd
assert cold[15328:15328 + 351270] == kd
```

单处相同可以解释为巧合或复制遗漏，三处同时相同则说明这是**原版资源被原样带入 Xbox 移植管线**，不是重新生成的字库。

## 2. 半角库：假名区被换成欧洲字符

两版都是 `7,680 = 256 × 30`（16×15 点阵，每行 2 字节）。逐槽（30 B 为一槽）比对：

- 相同 174 槽，不同 82 槽
- 差异槽号：`43`、`124`、`129–153`、`166–175`、`177–221`

| 槽区 | DC 日版内容 | 美版内容 |
|---|---|---|
| 0–42 | 拉丁字母／数字／标点 | 相同 |
| 43（`+`） | — | 字形不同 |
| 124（`\|`） | — | 字形不同 |
| 129–153 | 半角片假名起始段 | 欧洲重音字母起始段 |
| 166–221 | 半角假名与符号 | `Á â ü è é ë`、`▲ ★ ☎ ✿ ◆ ■ ♠ ♣ ↓ →` |

这说明该文件在美版里被改造成**英／法／德字幕用的西文扩展表**：ASCII 段保留，假名段整块替换。

渲染对照（上为美版，第 5 行起可见重音字母与图形符号；下为日版，同一区域是半角片假名）：

逐槽数据：`data/kana_slot_diff.csv`（`slot, same, xbox_md5, dc_md5`）。

## 3. RYOU：7806 槽部件库被丢弃

- DC：351,270 B，按 45 B/槽渲染是**符号表 + 汉字部件／大字**——箭头、方块、星、心、括号，以及「兆」这类部件。它不是标准汉字区的第二套，而是标题／招牌用的图形字库。
- 美版：7,680 B，256 槽，纯 ASCII 小字库，与 `dc_kana` 同规格（个别字形不同：`（` vs `－`、`＼` vs `￥`）。

三条交叉验证（`data/ryou_analysis.csv`）：

| 检查 | 结果 |
|---|---|
| 美版 == DC 前 7,680 B | 否 |
| 美版 == DC 后 7,680 B | 否 |
| 美版 == `DC_KANJI.FON` 首/尾 7,680 B | 否 |
| 美版片段在 DC 351,270 B 中出现位置 | `-1`（不存在） |

即原库确实没有随移植进入美版。若游戏有调用 `RYOU.FON` 的界面（标题、招牌类大字），这部分字形在美版里已不可用，需从 DC 取回并核对加载尺寸。

渲染对照：第一栏为 DC 版按 45 B/槽（正确布局），第二栏为同一文件按 30 B/槽（错误布局，整片散乱），第三栏为美版 256 槽 ASCII 表。

![RYOU 布局对照](assets/font_ryou_layout.png)

## 4. COLD.BIN

美版 `misc/COLD.BIN`：591,964 B，`714787F2AE47250BC059300E84F990F6`。内嵌汉字库整段仅出现 1 次，位于偏移 15328。

该文件在 DC 时代通常被视作"字形／调色相关容器"，本次只确认了它对汉字库的承载关系，未做更细的结构拆分。

## 5. 工程含义

| 用途 | 能否直接用美版 |
|---|---|
| 全角汉字（对白、菜单、笔记） | 可以，槽位与 DC 一致 |
| 简体补充字形 | 需在 7806 槽内扩容或替换 |
| 半角假名／西文标点 | 不能，美版已是西文表 |
| 标题／招牌大字（RYOU） | 不能，原库缺失 |
