# 文本符号语义：`A1C4` 与 `A1F5`

字幕文本里最容易出错的地方不是汉字，而是标点。本项目曾把两个字节记错，导致"两平台标点体系不同"的错误结论。记录如下，供后来者避坑。

## 1. 正确映射

| 字节 | 显示 | 作用 |
|---|---|---|
| `A1C4` | `…` | 省略号，句尾停顿 |
| `A1F5` | （换行） | 显式断行 |
| `A1A1` / `A1A2` | 顿号类 | 句中分隔 |
| `A1A3` | `。` | 句号 |
| `A1A9` | `？` | 问号 |

> 注意：不同资料对 `A1A1/A1A2` 的编号写法略有出入（JIS 区与 EUC 偏移），本项目只对 `A1C4`、`A1F5` 做了字节级与实机双向确认，其余按显示结果登记。

## 2. 曾经错在哪

早期笔记写作：

- 「DC 日版用 `…` 和 `/`」
- 「Xbox 用全角 `、`(A1C4) 和 `＆`(A1F5)」

两处都错在**按 EUC-JP 的字符名去理解字节**：`A1C4` 在 EUC 表里邻接顿号，`A1F5` 邻接全角符号，于是被想当然标成"顿号"与"＆"。而引擎渲染时：

- `A1C4` 出的是省略号 `…`
- `A1F5` 不是可见字符，是**换行控制**

旧笔记里那个 `/`，其实就是把 `A1F5` 的换行效果写成可读化标记 `/`，并非真的斜杠字节。两个版本从来没有标点差异。

## 3. 字节级验证

`0005.afs` / `RYO_STDL` / 第 0 条，DC 与 Xbox 两边的 20 字节一致：

```
A5 EF A5 F3 A5 C1 A5 E3 A5 A4   A1 C4   B9 C8 C6 EE B3 B9   A1 C4
A1 F5   B2 B8 C5 C4 CF B0   A1 C4
```

若 `A1C4` 是顿号、`A1F5` 是「＆」，这句话会读成「湾仔、紅南街、＆恩田楼、」——语义上明显不通，且末尾多余标点。按正确映射读则是「ワンチャイ…紅南街…<换行>恩田楼…」，与实机画面完全一致。

## 4. 实机验证（xemu v0.8.138）

同一场景连续两条字幕：

| 条目 | 屏幕显示 | 说明 |
|---|---|---|
| 第 2 条 | 第一行 `ワンチャイ…紅南街…`<br>第二行 `恩田楼…` | `A1C4` 出 `…`；`A1F5` 断行 |
| 第 1 条 | `桃李少老師は、ここに…` | 句中「、」是另一字节；句尾 `…` 为 `A1C4` |

同一批画面上，繁体字（`老師`、`紅南街`）显示正常，说明 `dc_kanji` 那套原版汉字库在美版里确实生效。

## 5. 对写盘的三条约束

1. **换行必须自己插**。字幕不会自动折行，长句需在语义停顿处插入 `A1F5`，否则溢出显示区。
2. **省略号不要写成 `...`**。三个 ASCII 点与 `A1C4` 在字宽和渲染上都不同，且会破坏与原文的字节对应。
3. **不要做"符号转换"**。既然两侧字节一致，任何把 `A1C4` 换成 `A1A1`、把 `A1F5` 换成别的东西的"规范化"，都会让文本对不上原盘。

## 6. 附带发现：贴图层不归文本管

同一场景里，凉手上那张纸条的毛笔字是 SPR 贴图，内容为「香港灣仔／紅南街／恩田楼二〇五／桃李少老師」。它不走 STREAM 文本表，汉化时需单独重绘，不计入文本覆盖率。
